HSK Chain Horizon Hackathon Seoul · Track 2: Agent Payments

Give each AI agent a budget it cannot overspend, enforced on HSK mainnet.

The owner sets a daily allowance, a per-payment limit, the shops the agent may pay and a cooldown. The agent must ask the contract before every payment. If the budget says no, the payment is blocked on chain with a plain reason, and only the owner can change the budget.

How it works, in three steps

  1. Owner sets the budget. Daily allowance, per-payment limit, listed shops, cooldown. Only the owner key can change it.
  2. Agent asks first. Every payment starts with requestPayment on the mainnet contract.
  3. Allowed or blocked. Within budget: the owner approves and a receipt is minted. Over budget: the call reverts with a plain reason.

      Paying through HSP

      HSP mock (QA access pending) HashKey's HSP QA gateway has not allowlisted us yet. Until it does, the HSP steps run against a mock that follows the documented shapes and checks real signatures. The budget contract and receipts above are real mainnet.

      1. Budget first. requestPayment on the vault. Blocked payments never reach HSP.
      2. Prepare. create_order → prepare_payment returns an EIP-712 payment mandate.
      3. Check before signing. Leash compares the EIP-712 data with the purchase: chain id, token, recipient = listed shop, value = the budget-checked amount. Any mismatch refuses.
      4. One human approval. The owner approves a card built from that checked message and signs in their own wallet; the vault records approve.
      5. Honest status. finalize_payment, then query_payment: payment-safe is shown as "confirming"; "finalized" only after payment-finalized.
      6. Receipt. settle stores hashes of flow_id, payment_request_id, the policy and the HSP tx on chain.

      Roadmap

      • Now Budget contract live and verified on HSK mainnet; owner/agent split; allowed, blocked and settled payments on chain.
      • Next Live HSP QA round trip once our access is allowlisted (no code change needed).
      • Then Several agents under one owner (buyer, data, ops), each with its own budget in the same contract.
      • Later Owner budget editor and spend alerts in a small web app.
